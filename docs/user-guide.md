# Pazom 使用文档

从账号准备、密钥创建到客户端接入、游乐场测试与问题排查，按步骤完成配置并稳定使用 Pazom 服务。

## 快速开始

1. 打开网站：https://pazom.xyz
2. 注册或登录账号；如果页面提供第三方登录，也可以按页面提示授权登录。
3. 进入“钱包/充值/兑换”相关页面，确认账户余额或额度可用。
4. 进入“API 密钥”页面，创建并复制自己的密钥。
5. 在客户端中填写接口地址和 API Key。
6. 先在“游乐场”或客户端里发送一条简单请求，确认模型可用后再正式使用。

## 账号注册与登录

- 使用邮箱注册时，请检查验证码邮件是否进入垃圾箱或拦截箱。
- 如果站点启用了第三方登录，请确保授权的是你自己的账号。
- 登录后如果访问某些页面提示无权限，通常代表当前账号不具备对应功能权限，或该功能尚未对当前分组开放。
- 如果忘记密码，可使用找回密码流程；若无法收到邮件，请联系站点支持。

## 余额、额度与签到奖励

- 站点会根据模型、分组、请求类型、输入输出量等因素计算消耗，实际扣费以日志中记录为准。
- “余额”和“额度”的展示单位以页面为准；如果页面同时展示美元或额度，请以充值页、钱包页或消费日志中的说明为准。
- 每日签到可能发放额度或余额奖励，奖励到账后通常会体现在钱包或额度展示中。
- 如果提示余额不足，请先充值、兑换或等待签到奖励到账后再发起请求。

## 创建和保护 API 密钥

API 密钥相当于你的访问凭证。请只在自己的客户端或可信服务器中使用，不要截图、公开分享或提交到代码仓库。

创建建议：

1. 进入“API 密钥”页面。
2. 点击创建密钥，填写便于识别的名称。
3. 如页面支持模型限制或 IP 白名单，可以按需限制密钥可用范围。
4. 创建后立即复制保存；部分页面只会显示一次完整密钥。
5. 如果怀疑泄露，请立即删除旧密钥并创建新密钥。

请求时使用以下 Header：

~~~http
Authorization: Bearer sk-你的密钥
Content-Type: application/json
~~~

## 在第三方客户端中使用

Pazom 提供 OpenAI 兼容接口，大多数支持自定义 OpenAI API 地址的客户端都可以使用。

基础配置：

| 配置项 | 填写内容 |
| --- | --- |
| API 地址 / Base URL | https://pazom.xyz/v1 |
| API Key | 在“API 密钥”页面复制的密钥 |
| 模型名称 | 使用页面中可见、当前账号可用的模型名 |
| 流式输出 | 聊天场景建议开启 |

常见客户端配置方式：

- Cherry Studio、Chatbox、Open WebUI、LobeChat 等客户端：选择 OpenAI 兼容提供商，填写 Base URL 和 API Key。
- 自写脚本或服务端程序：按 OpenAI 兼容格式请求 /v1/chat/completions、/v1/responses 或 /v1/images/generations。
- 如果客户端有“代理地址”“兼容模式”“自定义 Provider”等选项，请选择能自定义 Base URL 的 OpenAI 兼容模式。

聊天请求示例：

~~~bash
curl https://pazom.xyz/v1/chat/completions \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "你的模型名称",
    "messages": [
      {"role": "user", "content": "你好，请简单介绍一下你自己"}
    ],
    "stream": true
  }'
~~~

Responses API 示例：

~~~bash
curl https://pazom.xyz/v1/responses \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "你的模型名称",
    "input": "用三句话解释什么是 API 网关",
    "stream": true
  }'
~~~

图片生成示例：

~~~bash
curl https://pazom.xyz/v1/images/generations \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "生成一张赛博朋克城市夜景，高清，电影感",
    "size": "1024x1024",
    "n": 1
  }'
~~~

## 使用游乐场测试

游乐场适合在正式接入客户端前快速验证模型、密钥、分组和图片能力。

- 选择模型后，可以直接发送聊天消息测试回复速度和内容质量。
- 使用图片模型时，生成过程可能需要 2～3 分钟，请耐心等待。
- 如果支持图生图，请上传或选择客户端可识别的图片资源，避免使用已经失效或无法访问的链接。
- 刷新页面前请确认当前生成任务是否已经完成；如果任务状态丢失，可在用量或绘图日志中查看是否产生记录。
- 如果同一模型在游乐场可用、客户端不可用，优先检查客户端的 Base URL、API Key、模型名称和流式设置。

## 查看用量日志

用量日志可以帮助你确认每次请求的消耗、状态和错误原因。

你可以关注以下信息：

- 请求 ID：排查问题时最重要，请复制完整请求 ID。
- 模型：确认客户端实际请求的模型是否符合预期。
- 路径：区分聊天、Responses、图片生成等接口。
- 状态码：判断是认证问题、余额问题、限流问题还是上游错误。
- 输入/输出 Token：了解消耗来源。
- 响应时间和首字时间：判断是网络慢、排队慢还是生成时间长。
- 错误信息：提交反馈时请附上错误信息和请求 ID。

## 模型、分组与可用范围

- 不同账号分组可用的模型可能不同，请以模型页面、价格页面或客户端实际返回为准。
- 如果请求返回“模型不存在”“无可用渠道”“权限不足”等提示，可能是模型名称写错、当前分组未开放、余额不足或密钥限制导致。
- 同一个模型在不同分组的价格、速度和额度消耗可能不同。
- 复制模型名时请注意大小写、连字符、点号和后缀，避免客户端自动改写模型名。

## 常见问题与处理方法

### 401 或未授权

通常是 API Key 未填写、填写错误、Header 格式错误或密钥已被删除。请确认 Header 为 Authorization: Bearer sk-你的密钥。

### 403 或权限不足

当前账号、分组或 API Key 可能没有访问该模型或页面的权限。请检查模型名称、密钥限制、IP 白名单和账户状态。

### 余额不足

请充值、兑换或等待签到奖励到账。请求失败前已经产生的上游消耗是否计费，以消费日志为准。

### 404 或模型不存在

请确认模型名称来自站点页面或服务方提供的列表，不要使用客户端默认模型名直接请求。

### 408 或请求超时

表示等待上游响应超过当前阈值。可以重试、换模型、关闭复杂工具调用，或稍后再试。

### 429 或限流

请求过快、并发过高或上游繁忙时可能出现。请降低并发，等待一段时间后重试。

### 500 或上游错误

通常代表上游服务异常、模型临时不可用或请求格式不被支持。请记录请求 ID 和错误信息后反馈。

### 流式输出中断

请检查网络代理、客户端流式设置和是否存在长时间无输出。可以临时关闭流式进行对比测试。

### 图片无法显示或无法二次图生图

请确认客户端支持返回的图片格式。某些图生图流程需要 base64 图片内容；如果客户端只保存了临时链接，链接过期或不可访问时可能导致后续图生图失败。

## 安全建议

- 不要把 API Key 发给他人，也不要放进公开仓库、公开截图或浏览器插件不可信配置中。
- 为不同设备或客户端创建不同密钥，便于单独删除和排查。
- 如果支持 IP 白名单，服务器端调用建议开启白名单限制。
- 定期检查用量日志，发现异常消耗时立即删除密钥并联系站点支持。
- 不要在提示词中提交密码、Cookie、验证码、银行卡、身份证等敏感信息。

## 反馈问题时请提供

为了更快定位问题，反馈时建议提供：

- 请求 ID；
- 发生时间；
- 使用的模型；
- 请求路径，例如 /v1/chat/completions、/v1/responses、/v1/images/generations；
- 客户端名称和版本；
- 错误状态码和错误信息；
- 是否流式、是否图片生成、是否使用工具调用。

请不要提供完整 API Key、密码、Cookie 或其他敏感凭证。
